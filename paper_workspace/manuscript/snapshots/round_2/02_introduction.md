# Introduction {#sec:intro}

The open `SKILL.md` packaging format has rapidly transformed how Large Language Model (LLM) coding agents acquire reusable procedures, bundling natural-language instructions, helper scripts, and reference templates into filesystem folders loaded on demand [@destefanis2026gitskills; @xu2026agentskills]. Yet empirical audits of this ecosystem reveal severe engineering fragility. Mining 3,797,117 public `SKILL.md` files across 282,200 GitHub repositories, @destefanis2026gitskills observe that natural-language skills lack compilers, type checkers, or centralized package verifiers. Across 138,133 public skills, @zhang2026reusable find that 91.8% contain at least one defect—dominated by bloated instruction bodies, broken metadata, and disorganized resources—while SkillsBench [@li2026skillsbench] evaluates 87 tasks across 8 domains and 18 model-harness configurations, showing that curated skills lift average task pass rates from 33.9% to 50.5% (+16.6 percentage points) and that focused skills (at most three modules) outperform larger exhaustive bundles. Simultaneously, security evaluations report substantial vulnerability rates across community registries [@xu2026agentskills; @badhe2026skillsecurity], up to 80% attack success rate (ASR) on skill-file prompt injections [@schmotz2026skillinject], and semantic supply-chain hijacking of skill discovery and governance [@saha2026underhood].

Academic research and paper authoring stress every weakness of current Agent Skill designs at once. A full research lifecycle spans literature discovery, experimental design, reproducible script execution, visualization, manuscript drafting, peer review, and double-blind LaTeX compilation. Existing automated scientific writers—such as The AI Scientist [@lu2024aiscientist], The AI Scientist-v2 [@yamada2025aiscientistv2], CycleResearcher [@weng2024cycleresearcher], and PaperOrchestra [@song2026paperorchestra]—operate as standalone automated systems outside interactive coding-agent skill ecosystems. Even when decoupled from fixed experiment loops, as in PaperOrchestra [@song2026paperorchestra], monolithic authoring pipelines leave four unresolved challenges for interactive coding-agent harnesses:

1. **Context bloat and harness lock-in:** Loading an entire multi-stage research workflow into one monolithic skill exceeds host loader limits (such as Antigravity's observed 24 KB / 24,000-byte skill ceiling), wastes prompt context on inactive stages, and prevents portability across Antigravity, Claude Code, and Codex.
2. **Silent provenance and conversion drift:** Without deterministic checks binding manuscript numbers to canonical non-synthetic run logs and citations to saved primary-source snapshots, drafting and Markdown-to-LaTeX conversion silently introduce fabricated decimals, synthetic dry-run leakage, unverified references, or dropped equations and labels.
3. **Intrinsic self-review bias:** As @huang2024selfcorrect demonstrate, LLMs cannot reliably self-correct reasoning in the same generation context without external feedback. Asking the drafting session to critique its own paper fails to catch missing ablations, claim-vs-source contradictions, or subtle anonymity leaks.
4. **Scientific supply-chain attack surfaces:** Scientific authoring uniquely ingests untrusted external data—scraped paper abstracts, user PDFs, and third-party conference LaTeX archives—exposing agents to indirect prompt injection [@greshake2023indirect], Zip Slip archive traversal, LaTeX `\write18` or `\input{|...}` shell pipes, arbitrary filesystem writes during compilation, and double-blind metadata leakage in compiled PDFs.

To address these challenges, we design and evaluate **PaperOEGM** (Paper Orchestra + Elephant-Goldfish Model, adopting the Elephant-Goldfish metaphor of preserving durable workspace memory while resetting reviewer context to fresh eyes [@google2026egm]). PaperOEGM is a composable, zero-API-key Agent Skills plugin packaged for Antigravity (live-verified end to end), Claude Code (CLI packaging- and install-validated), and Codex (structurally packaged). It runs exclusively on the user's active coding-agent runtime with zero external LLM API keys and zero third-party Python dependencies for its core verifier (`po_tools.py`), using optional `matplotlib` only for Stage 5 quantitative plotting. Its core principle is a strict separation between *deterministic mechanical verification* and *fresh-context semantic critique*, illustrated in Figure~\ref{fig:architecture}.

PaperOEGM organizes the workflow into ten chronological progressive-disclosure skills (`po-start` through `po-format`), each capped at 12,000 bytes with `disable-model-invocation: true` so the host agent never triggers destructive or premature transitions autonomously. Shared state lives in a single authoritative `paper_state.json` tracked by `po_tools.py`, which audits SHA-256 input-digest drift, verifies BibTeX-to-ledger-to-snapshot parity, validates inline `run:<id>` numeric blocks against canonical non-synthetic `metrics.json`, checks `.md`-to-`.tex` conversion parity, scans archives for Zip Slip and TeX shell pipes, and enforces double-blind hygiene. Because mechanical checks alone cannot catch semantic flaws such as citation distortion or integer-only falsification, PaperOEGM pairs `po_tools.py` with five stateless, read-only critic subagents dispatched *flat at depth one* in parallel (avoiding nested synthesizer topologies that fail on non-nesting runtimes), bounded to 1,500 output tokens each and verified via pre/post SHA-256 snapshots (`check-readonly`).

This paper makes four empirical and engineering contributions:

* **Modular zero-API-key multi-harness skill architecture (Section~\ref{sec:method}):** We formalize a 10-skill progressive-disclosure graph, single-source state schema, safe offline experiment runner contract (`--dry-run` isolation, atomic `metrics.json`, `EXIT` traps), flat 1-level read-only critic topology, paranoid LaTeX build wrapper, and deterministic ZIP packager across Antigravity, Claude Code, and Codex.

* **PO-FaultBench and deterministic boundary analysis (Section~\ref{sec:exp-rq1}):** Across an author-constructed 120-workspace fault-injection corpus (80 faults across 8 families plus 40 hard negative controls per seed) and 20 adversarial evasion cases per seed over five seeds, `po_tools.py` achieves 100.0% recall and 0.0% false-positive rate (FPR) on mechanical faults in 108.20 ms/workspace, outperforming Compiler-Only (6.25% recall) and No-Inline-Provenance ablations (87.5% recall), while dropping to 0.0% recall on semantic and macro-obfuscation evasions—empirically delineating the boundary requiring native TeX containment and semantic critics.

* **Packaging context economics and build determinism (Section~\ref{sec:exp-rq2}):** PaperOEGM cuts median active-stage prompt context by 82.16% (97.14% startup index reduction) relative to a monolithic baseline, maintains 81.14% headroom below Antigravity's 24 KB (24,000-byte) skill ceiling (where the public EGM reference plugin [@google2026egm] reaches 24,257 bytes), passes `claude plugin validate` with 0 defects, and achieves 100.0% deterministic ZIP SHA-256 parity.

* **Scalability, context offloading, and paranoid TeX containment (Section~\ref{sec:exp-rq3}):** Across 20 to 120 citations and 5 to 30 runs, all four verifier subcommands finish in 266.00 ms to 268.55 ms, offload 87.82%--87.96% of raw metadata from `citation_ledger.json` (loaded on demand during citation auditing), compile three double-blind venues with zero identity leaks, and empirically verify paranoid TeX containment—blocking obfuscated shell escapes and parent-directory writes while uncovering an upstream TeX Live 2026 `openin_any=p` no-op regression.

* **Live hybrid fresh-context critic evaluation (Section~\ref{sec:exp-rq4}):** Across three distinct seeded domain manuscripts containing 30 planted flaws (15 mechanical, 15 semantic), deterministic verification recovers 100.0% of mechanical flaws in 91.71 ms but 0.0% of semantic flaws (50.0% total), whereas 15 live flat-parallel Antigravity read-only critic invocations recover 100.0% of planted semantic flaws (lifting recall to 100.0%) with 0.0 clean-control false positives, 0 workspace mutations, and peak output within the 1,500-token budget. We candidly report negative results, baseline gaps, and threats to validity in Section~\ref{sec:limitations}.
