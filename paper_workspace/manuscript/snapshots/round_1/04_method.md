# System Design {#sec:method}

PaperOEGM is packaged as a zero-API-key multi-harness plugin targeting Antigravity, Claude Code / Cowork, and Codex. Its architecture rests on four design invariants: (1) strict progressive-disclosure skill budgets with human-controlled transitions, (2) deterministic zero-dependency verification over a single-source workspace state, (3) flat single-level fresh-context read-only peer review, and (4) defense-in-depth build and supply-chain safety.

## Progressive-Disclosure Skill Graph and State Machine {#sec:method-skills}

Rather than loading an entire writing playbook upfront, PaperOEGM partitions the research-to-paper lifecycle into ten chronologically ordered skills under `skills/po-*/SKILL.md`, organized across three phases (Figure~\ref{fig:architecture}, Layer 1):

* **Phase 1 — Intake and Experiments:** Stage 0 `po-start` (workspace routing, secret denylist intake, toolchain probe), Stage 1a `po-literature` (early primary-source survey), Stage 2 `po-exp-design` (falsifiable hypotheses, baselines, ablations, metric schema), and Stage 3 `po-exp-code` (safe parameterized bash runners and offline `--dry-run` smoke tests).
* **Phase 2 — Evidence and Drafting:** Stage 4 `po-outline` (canonical vs. planned evidence reconciliation and page budgeting), optional Stage 1b `po-literature` (late Related Work pass), Stage 5 `po-visuals` (code-rendered plots from canonical logs plus multimodal visual audit), and Stage 6 `po-draft` (modular LaTeX-friendly Markdown sections with inline provenance tags).
* **Phase 3 — Independent Review and Venue Delivery:** Stage 7 `po-review` (deterministic preflight + five flat parallel read-only critics), Stage 8 `po-resolve` (reversible snapshots and three-bucket finding triage), and Stage 9 `po-format` (Pandoc conversion, paranoid LaTeX compilation, `pdfinfo` hygiene, and post-compile PDF layout critique).

Every skill obeys three packaging invariants derived from empirical skill-reuse studies [@zhang2026reusable; @li2026skillsbench]. First, every `SKILL.md` is capped at `<= 250` lines and `<= 12,000` bytes (half of Antigravity's `24,000`-byte loader limit), offloading shared rules into six stage protocols (`resources/protocols/`) and five review standards (`resources/review_standards/`) loaded only when invoked. Second, every skill declares `disable-model-invocation: true` in its YAML frontmatter, preventing autonomous unprompted stage jumps and enforcing explicit single-select human approval gates at every stage boundary. Third, every stage reads and updates a single authoritative state file, `paper_state.json`, which owns `project_title`, `venue` (`name`, `template_year`, `submission_mode`, `page_limit_main`), `environment` toolchain capabilities, and per-stage `input_hashes` and `output_hashes` (SHA-256). A human-readable `STATUS.md` dashboard is regenerated atomically from `paper_state.json` on every sync so configuration never drifts across duplicated files.

To formalize context efficiency, let $B_{\text{mono}}$ denote the total byte size of loading all ten skills, shared execution rules, six protocols, and five review standards monolithically, $B_{\text{stage}}(s)$ the active byte footprint of skill $s$ plus its referenced protocols, and $B_{\text{idx}}$ the startup YAML frontmatter index across all skills. We quantify per-stage prompt context reduction $R_{\text{ctx}}$ and startup index reduction $R_{\text{idx}}$ as:

$$R_{\text{ctx}} = \left(1 - \frac{\operatorname{median}_{s} B_{\text{stage}}(s)}{B_{\text{mono}}}\right) \times 100\%, \quad R_{\text{idx}} = \left(1 - \frac{B_{\text{idx}}}{B_{\text{mono}}}\right) \times 100\%$$ {#eq:context-reduction}

## Zero-Dependency Deterministic Verifier (`po_tools.py`) {#sec:method-verifier}

To avoid fragile runtime `pip install` hooks and provide external feedback independent of LLM stochasticity [@huang2024selfcorrect], PaperOEGM bundles `resources/scripts/po_tools.py`, a 758-line Python 3.10+ standard-library CLI implementing four deterministic subcommands (Figure~\ref{fig:architecture}, Layer 2):

1. **`state-sync`:** Validates `paper_state.json` atomically (`tmp` + `os.replace`), probes local tool binaries (`pandoc`, `latexmk`/`pdflatex`, `bibtex`, `pdftoppm`, `matplotlib`), counts unresolved placeholder markers (explicit `TODO` and pending-run tags), recomputes SHA-256 digests of every approved stage's inputs, and flags upstream-modified downstream stages as `stale`.
2. **`check-readonly`:** Captures (`--create`) and verifies (`--verify`) a deterministic SHA-256 inventory of all tracked files strictly inside the active paper workspace before and after read-only critic execution. Any added, modified, or deleted file triggers exit code 1, providing runtime tamper detection on harnesses lacking hard filesystem-level write locks.
3. **`review-preflight`:** Executes mechanical provenance checks prior to spawning LLM critics:
   * *Citation and snapshot parity:* Extracts every Pandoc (`[@key]`, `@key`) and LaTeX (`\cite*{key}`) citation across `manuscript/sections/*.md` (stripping fenced code blocks and HTML comments), verifying 1:1 presence in both `literature/references.bib` and `literature/citation_ledger.json`, blocking any `unverified_needs_human_check` entry, and verifying that every `verified_source` entry resolves to an existing raw primary-source file under `literature/sources/`.
   * *Non-synthetic and BYO provenance:* Rejects any manuscript reference to the isolated `dry_run/` smoke-test directory, any run marked `is_synthetic: true` in `provenance_index.json`, `run_manifest.json`, or `metrics.json`, and any `origin: "user_byo"` run lacking `user_attested_non_synthetic: true`, while surfacing `git_dirty: true` runs as Major warnings.
   * *Inline run-to-metric matching:* Parses every inline provenance marker `<!-- run:<run_id> -->` and audits every decimal token $v$ with $d$ fractional digits in the immediately following paragraph or table block against the flattened numeric set $\mathcal{M}(r)$ of canonical `metrics.json` for run $r$. A decimal token $v$ passes if there exists $m \in \mathcal{M}(r)$ satisfying:

   $$\min\Big(|m - v|,\; \mathbb{I}[0 \le m \le 1]\cdot|100m - v|\Big) \le \epsilon(d), \quad \epsilon(d) = 0.55 \times 10^{-d}$$ {#eq:decimal-match}

   where $\mathbb{I}[\cdot]$ is the indicator function permitting standard proportion-to-percentage conversion (e.g., $0.854 \to 85.4\%$) and $\epsilon(d)$ accommodates half-up/half-even rounding without tolerating fabricated shifts. Crucially, `po_tools.py` restricts automated regex matching to decimal tokens (`\d+\.\d+`) to prevent false alarms on section numbers, epoch counts, or hardware specs—deliberately delegating integer-count auditing to `po-evidence-auditor`.
4. **`format-verify`:** Enforces supply-chain, conversion, and anonymity invariants across Stage 9: inspects `.zip` and `.tar.*` template archives for Zip Slip (`..` or leading `/`), symlink/hardlink members, and active TeX shell-pipe primitives (`\write18`, `\immediate\write18`, `\input{|...}`) after stripping `%` comments; verifies `.md`-to-`.tex` parity across citations, `\label{}` anchors, and non-dimension decimal tokens (filtering LaTeX units such as `0.85\linewidth` and `10.5pt`); parses TeX `.log` and `.aux` telemetry for undefined references, missing graphics, and `Overfull \hbox > 2pt` warnings; and scans all submission `.tex` files (including `%` comments) for local paths (`/Users/`, `/home/`, `C:\Users\`), non-anonymous GitHub URLs, and camera-ready toggles (`\iclrfinalcopy`, `\usepackage{cvpr}`) whenever `submission_mode == "double-blind"`.

## Experiment Safety, Visual Provenance, and Context Offloading {#sec:method-safety}

To prevent research scripts from mutating user source code or contaminating paper tables with smoke-test outputs, Stage 3 (`po-exp-code`) enforces a safe bash runner template: `set -euo pipefail`, double-quoted paths, offline telemetry defaults (`WANDB_MODE=offline`), startup `run_manifest.json` creation paired with `trap finalize EXIT` (guaranteeing crash-safe `finished_at` and `exit_code` logging), non-git fallback (`git_commit: "none"`, `git_dirty: null`), CLI secret and `$HOME` redaction in logged `cmd` strings, atomic writes (`metrics.json.tmp` renamed via `os.replace`, capped under 10 KB), and isolated `--dry-run` execution writing exclusively to a segregated `dry_run/<run_id>/` tree with `is_synthetic: true`.

Two additional mechanisms protect context budgets and visual integrity. First, rather than embedding full paper abstracts inside `citation_ledger.json`, Stage 1 stores raw primary-source API snapshots in `literature/sources/<citekey>.json` and keeps only compact pointers and 1–2 sentence summaries in `citation_ledger.json`. Let $S_{\text{led}}$ and $S_{\text{src}}$ denote the byte sizes of `citation_ledger.json` and `literature/sources/`, respectively; the context offload ratio is $R_{\text{off}} = (1 - S_{\text{led}} / (S_{\text{led}} + S_{\text{src}})) \times 100\%$. Second, Stage 5 (`po-visuals`) mandates that all newly generated quantitative plots be rendered by version-controlled Python scripts reading directly from canonical non-synthetic `metrics.json` or `series.csv` (zero hardcoded data arrays and zero generative raster tools on numerical plots), exporting colorblind-safe, dual-encoded vector PDFs with stripped metadata alongside high-DPI PNG previews inspected visually before recording `VISUAL_AUDIT: COMPLETED`.

## Flat Read-Only Critic Topology, Paranoid TeX Sandbox, and Multi-Harness Packaging {#sec:method-critics}

Stage 7 (`po-review`) spawns five stateless read-only critic personas (`agents/po-*.md`, each `<= 6,000` bytes) **flat at depth one in parallel** directly from the root session (Figure~\ref{fig:architecture}, Layer 3a): `po-peer-reviewer` (originality, ablations, overclaims, prose anonymity), `po-evidence-auditor` (decimal and integer metric fidelity, BYO/synthetic provenance, plot script alignment), `po-citation-auditor` (offline BibTeX/ledger parity and claim-vs-source abstract fidelity), `po-visual-format-critic` (multimodal figure legibility in Stage 7 and chunked 4–5 page PDF layout review in Stage 9), and `po-clarity-reader` (naive external reader auditing undefined notation, unexplained acronyms, and logical jumps). Unlike EGM's nested `synthesizer` agent [@google2026egm], flat parallel dispatch eliminates nesting failures across Antigravity and Claude Code Cowork, caps each critic at 1,500 output tokens, and logs a 4-state `Reviewer Status` ledger (`completed`, `failed`, `timed_out`, `skipped_unavailable`) so missing critics are never silently equated with zero defects. On Claude Code, five matching read-only adapters (`.claude-plugin/agents/po-*.md`) restrict each critic's `tools:` allowlist strictly to `Read, Grep, Glob`.

Because regex scanning of LaTeX sources (`SHELL_PIPE_RE`) can be bypassed by macro indirection (e.g., `\csname write18\endcsname`), Stage 9 (`po-format`) compiles all venue builds inside a paranoid native TeX wrapper (`openin_any=p openout_any=p pdflatex -interaction=nonstopmode -halt-on-error --no-shell-escape`), suppresses PDF identity metadata via `\hypersetup{pdfauthor={},pdfcreator={},pdfproducer={}}` and TeX trailer directives, and audits compiled PDFs with `pdfinfo`. Finally, `scripts/pack_plugin.py` synchronizes all five manifests (`plugin.json`, `.claude-plugin/{plugin,marketplace}.json`, `.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json`) and emits byte-reproducible ZIP archives (fixed ZIP timestamps `1980-01-01`, sorted traversal, normalized permissions) across Antigravity, Claude Code, and Codex.
