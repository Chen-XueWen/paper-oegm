# Related Work {#sec:related}

PaperOEGM sits at the intersection of four research threads: Agent Skill packaging and benchmarking, skill security auditing, automated scientific discovery and paper writing, and fresh-context LLM peer review.

## Agent Skill Packaging and Context Economics

Agent Skills encapsulate domain procedures as Markdown (`SKILL.md`) directories paired with optional scripts and reference files loaded through progressive disclosure [@xu2026agentskills; @destefanis2026gitskills]. Prior work on Agent-Computer Interfaces (ACIs) demonstrated that tool interface design and structured feedback loops strongly govern coding-agent success [@yang2024sweagent]. Large-scale mining of public skill repositories shows that authoring practice lags behind specification intent: @destefanis2026gitskills catalog 3,797,117 `SKILL.md` files (1,877,981 unique contents) across 282,200 GitHub repositories and note the absence of static type checkers or package verifiers. @zhang2026reusable audit 138,133 public skills across 20,556 repositories and find that 91.8% exhibit at least one defect—chiefly packaging bloat, malformed routing metadata, and unstructured reference folders—and confirm on a 20,000-skill startup routing test that specification-compliant metadata improves retrieval accuracy.

Benchmarking utility directly, SkillsBench [@li2026skillsbench] evaluates 87 tasks across 8 domains and 18 model-harness pairs, showing that curated skills increase average pass rates from 33.9% to 50.5% (+16.6 percentage points), while focused, modular skills (at most three modules) consistently outperform exhaustive monolithic manuals. SkillTester [@wang2026skilltester] similarly combines paired baseline-vs.-with-skill runs with security probes to produce normalized utility and security labels. Closest in packaging philosophy to our system is the Elephant-Goldfish Model (EGM) [@google2026egm], a multi-harness coding-agent plugin targeting Antigravity, Claude Code, and Codex with fresh-context Goldfish review personas for engineering design specifications. However, EGM does not address experimental execution safety, quantitative run-to-manuscript provenance, verified citation ledgers, or double-blind LaTeX sandboxing, and its review loop relies on a nested `synthesizer` subagent that fails on runtimes prohibiting nested subagent spawning. PaperOEGM adapts EGM's multi-harness packaging and fresh-context separation to scientific research while enforcing stricter skill size budgets (`<= 12 KB`), flat 1-level dispatch, and a bundled zero-dependency deterministic verifier.

## Skill Security, Prompt Injection, and Supply-Chain Auditing

Because skills blend executable scripts and natural-language instructions, they inherit and amplify Indirect Prompt Injection threats [@greshake2023indirect]. Recent 2026 studies quantify this attack surface systematically. Skill-Inject [@schmotz2026skillinject] evaluates 202 context-dependent injection-task pairs and observes up to 80% attack success rate (ASR) on frontier LLMs, concluding that neither model scaling nor naive input filtering suffices without context-aware authorization. @saha2026underhood demonstrate `SKILL.md`-only semantic supply-chain attacks on public skill registries that achieve up to 86% retrieval win rate, 77.6% selection bias, and 36.5%–100% governance evasion. Survey and lifecycle security analyses [@xu2026agentskills; @badhe2026skillsecurity] report that 26.1% of community skills exhibit security vulnerabilities across acquisition, execution, and maintenance stages. To counter cross-file obfuscation, @lv2026structuredaudit propose SkillGuard-Robust for structured security auditing of untrusted skill bundles.

While these works examine general-purpose skill registries, scientific authoring skills introduce domain-specific supply-chain vectors: untrusted conference template archives containing Zip Slip paths or LaTeX `\write18`/`\input{|...}` shell escapes, external literature metadata containing injected instructions, secret leakage into logged bash commands, and accidental author deanonymization via LaTeX `%` comments or PDF `/Author`/`/Creator` metadata. PaperOEGM directly defends these scientific vectors by combining static pre-extraction scanning, native paranoid TeX I/O isolation (`openin_any=p`, `openout_any=p`, `--no-shell-escape`), secret redaction in runner manifests, and `pdfinfo` metadata auditing.

## Automated Research and Paper-Writing Systems

End-to-end automated discovery pipelines—including The AI Scientist [@lu2024aiscientist], The AI Scientist-v2 [@yamada2025aiscientistv2], and CycleResearcher [@weng2024cycleresearcher]—couple hypothesis generation, code execution, paper drafting, and simulated review inside autonomous loops backed by commercial LLM APIs or dedicated post-trained open-weight models. Yet PaperBench [@starace2025paperbench] (20 ICML 2024 Spotlight and Oral papers decomposed into 8,316 rubric items) shows that frontier autonomous agents replicate only 21.0% of research end to end, underscoring the need for human-in-the-loop checkpoints and rigorous provenance tracking rather than unattended generation.

Decoupling manuscript composition from experiment execution, PaperOrchestra [@song2026paperorchestra] transforms unstructured research materials into LaTeX papers via coordinated subagents, outperforming autonomous baselines by 50%–68% on literature review and 14%–38% overall quality win margins on the 200-paper PaperWritingBench benchmark. PaperBanana [@zhu2026paperbanana] focuses specifically on automated academic illustration via Vision-Language Models (VLMs) and generative image refinement. However, PaperOrchestra operates as a standalone, API-key-dependent Python pipeline invoked only after experiments finish; it lacks interactive pre-experiment stage skills, deterministic verification linking manuscript numbers to non-synthetic run manifests, strict separation between code-rendered quantitative plots and non-quantitative diagrams, and cross-harness Agent Skill distribution. PaperOEGM bridges this gap as a zero-API-key plugin supporting both full research lifecycles (`po-start` through `po-format`) and bring-your-own (BYO) log entry points.

## Self-Correction Limits and Fresh-Context Peer Review

Empirical work on LLM self-refinement shows that intrinsic self-correction without external feedback fails to improve—and often degrades—reasoning accuracy [@huang2024selfcorrect]. Conversely, large-scale peer-review studies indicate substantial utility when LLM critiques are structured independently: analyzing 3,096 Nature-family and 1,709 ICLR papers alongside a 308-researcher survey, @liang2024feedback find that LLM feedback overlaps with human reviewers (30.85% on Nature, 39.23% on ICLR) at rates comparable to inter-human overlap (28.58% and 35.25%), with 57.4% of researchers rating the feedback helpful while noting persistent factual-verification weaknesses. PaperOEGM operationalizes these findings directly: deterministic `po_tools.py` supplies reliable external mechanical verification, while five fresh-context read-only critics supply independent semantic review without polluting or mutating the author's drafting workspace.
