# Limitations and Threats to Validity {#sec:limitations}

To keep PaperOEGM's claims strictly calibrated to empirical evidence, we highlight six limitations and threats to validity.

**Self-Benchmark Circularity in PO-FaultBench.** Because both `po_tools.py` and PO-FaultBench (`exp01`) were authored together, the 100.0% recall and 0.0% FPR on families F1–F8 confirm implementation fidelity against PaperOEGM's own specification rather than universal detection against arbitrary real-world paper errors. We mitigated inflation bias by pairing F1–F8 with 40 hard negative controls and a 20-case adversarial evasion suite (`exp01_evasion`), where deterministic recall drops to 0.0%. External validation on third-party paper corpora (such as PaperBench [@starace2025paperbench] or historical conference errata) remains future work.

**Deterministic Security Boundaries.** Regex-based TeX scanning (`SHELL_PIPE_RE`) cannot catch macro-obfuscated TeX escapes such as `\csname write18\endcsname` (0.0% recall on E2 in `exp01`). PaperOEGM therefore treats regex scanning strictly as a fast pre-extraction filter and delegates hard execution containment to native TeX engine flags (`openin_any=p`, `openout_any=p`, `--no-shell-escape`). Similarly, as shown by @schmotz2026skillinject, natural-language instructions alone cannot guarantee immunity against adaptive indirect prompt injection inside scraped paper abstracts or user PDFs; human checkpoint gates and read-only critic sandboxing bound blast radius rather than eliminating prompt injection completely.

**Scope of Live Hybrid Critic Evaluation (`exp04`).** Operating under a strict zero-external-API-key constraint, our live multi-critic experiment evaluates $n=3$ compact seeded domain manuscripts (30 planted flaws across 15 live subagent invocations) on a single host runtime and model (Antigravity). While this establishes multi-domain variance and real multimodal figure inspection without paid API keys, it does not measure critic recall degradation on full 9-page manuscripts with 80+ references, nor does it quantify variance across distinct frontier models or live Claude Code / Codex critic sessions. Moreover, achieving 100.0% critic recall on compact drafts reflects dense, unambiguous planted flaws; subtler methodological flaws on long manuscripts will incur lower recall, consistent with @liang2024feedback's human-vs.-LLM overlap findings.

**Asymmetric Cross-Harness Verification.** Antigravity execution (all 10 skills and 5 live read-only subagents) and Claude Code CLI packaging (`claude plugin validate`, local marketplace registration, and plugin installation) were live-verified. Codex / ChatGPT Work support is structurally verified through synchronized manifests (`.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json`, `agents/openai.yaml`) and deterministic packaging tests, but has not been live-executed in an interactive Codex CLI session.

**Venue Class Metadata Quirks and Startup Latency.** Our `exp03` audit revealed two practical systems trade-offs: invoking `po_tools.py` as four separate Python CLI processes incurs ~260 ms of cold interpreter and `shutil.which` overhead regardless of workspace size (making a single batched subcommand an attractive future optimization), and `acmart` v2.16 populates a generic `Creator: LaTeX with acmart ...` tag via `hyperxmp` even when `\hypersetup{pdfcreator={}}` is specified. Although non-identifying (`0` personal leaks), authors targeting strict metadata-scrubbing venues should inspect `pdfinfo` output after compilation.

**Human Accountability and Authorship Scope.** PaperOEGM is designed strictly as a human-in-the-loop workflow aid with explicit approval gates (`disable-model-invocation: true`), not an autonomous paper mill. Human researchers remain responsible for scientific validity, IRB/ethics compliance, real experiment execution, and final verification of every citation and numerical claim prior to submission.
