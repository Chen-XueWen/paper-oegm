# System Design {#sec:method}

PaperOEGM is packaged as a zero-API-key multi-harness plugin targeting Antigravity, Claude Code, and Codex. Its architecture rests on four design invariants: (1) strict progressive-disclosure skill budgets with human-controlled transitions, (2) deterministic zero-dependency verification over a single-source workspace state, (3) flat single-level fresh-context read-only peer review, and (4) defense-in-depth build and supply-chain safety.

## Progressive-Disclosure Skill Graph and State Machine {#sec:method-skills}

Rather than loading an entire writing playbook upfront, PaperOEGM partitions the research-to-paper lifecycle into ten modular skills under `skills/po-*/SKILL.md` (with `po-literature` invoked in two distinct passes—Stage 1a early survey and optional Stage 1b late Related Work refresh), organized across three phases (Figure~\ref{fig:architecture}, Layer 1):

* **Phase 1 — Intake and Experiments:** Stage 0 `po-start` (workspace routing, secret denylist intake, toolchain probe), Stage 1a `po-literature` (early primary-source survey), Stage 2 `po-exp-design` (falsifiable hypotheses, baselines, ablations, metric schema), and Stage 3 `po-exp-code` (safe parameterized bash runners and offline `--dry-run` smoke tests).
* **Phase 2 — Evidence and Drafting:** Stage 4 `po-outline` (canonical vs. planned evidence reconciliation and page budgeting), optional Stage 1b `po-literature` (late Related Work pass), Stage 5 `po-visuals` (code-rendered plots from canonical logs plus multimodal visual audit), and Stage 6 `po-draft` (modular LaTeX-friendly Markdown sections with inline provenance tags).
* **Phase 3 — Independent Review and Venue Delivery:** Stage 7 `po-review` (deterministic preflight plus five flat parallel read-only critics), Stage 8 `po-resolve` (reversible snapshots and three-bucket finding triage separating mechanical fixes, scientific decisions, and optional polish), and Stage 9 `po-format` (Pandoc conversion, paranoid LaTeX compilation, `pdfinfo` hygiene, and post-compile PDF layout critique).

Every skill obeys three packaging invariants informed by empirical skill-reuse studies [@zhang2026reusable; @li2026skillsbench]. First, every `SKILL.md` is capped at `<= 250` lines and `<= 12,000` bytes (half of Antigravity's observed 24 KB / 24,000-byte skill loader ceiling), offloading shared rules into `execution_instructions.md`, six stage protocols (`resources/protocols/`), and five review standards (`resources/review_standards/`) loaded only when invoked. Second, every skill declares `disable-model-invocation: true` in its YAML frontmatter, preventing autonomous unprompted stage jumps and enforcing explicit single-select human approval gates at every stage boundary. Third, every stage reads and updates a single authoritative state file, `paper_state.json`, which owns `project_title`, `venue` (`name`, `template_year`, `submission_mode`, `page_limit_main`), `environment` toolchain capabilities, and per-stage `input_hashes` and `output_hashes` (SHA-256). A human-readable `STATUS.md` dashboard is regenerated atomically from `paper_state.json` on every sync so configuration never drifts across duplicated files.

To formalize context efficiency, let $B_{\text{mono}}$ denote the total byte size of loading all ten `SKILL.md` files, shared `execution_instructions.md`, six protocols, and five review standards monolithically; let $B_{\text{stage}}(s)$ denote the active byte footprint of skill $s$ (`SKILL.md` plus `execution_instructions.md` and every protocol file directly referenced by $s$); and let $B_{\text{idx}}$ denote the combined startup YAML frontmatter index across all ten skills. We quantify per-stage prompt context reduction $R_{\text{ctx}}$ and startup index reduction $R_{\text{idx}}$ as:

$$R_{\text{ctx}} = \left(1 - \frac{\operatorname{median}_{s} B_{\text{stage}}(s)}{B_{\text{mono}}}\right) \times 100\%, \quad R_{\text{idx}} = \left(1 - \frac{B_{\text{idx}}}{B_{\text{mono}}}\right) \times 100\%$$ {#eq:context-reduction}

## Zero-Dependency Deterministic Verifier (`po_tools.py`) {#sec:method-verifier}

To avoid runtime `pip install` dependencies and supply external mechanical verification independent of LLM stochasticity [@huang2024selfcorrect], PaperOEGM bundles `resources/scripts/po_tools.py`, a 758-line Python 3.10+ standard-library CLI implementing four deterministic subcommands (Figure~\ref{fig:architecture}, Layer 2):

1. **`state-sync`:** Validates `paper_state.json` atomically (`tmp` + `os.replace`), probes local binaries (`pandoc`, `latexmk`/`pdflatex`, `bibtex`, `pdftoppm`, and optional `matplotlib`), counts unresolved placeholder markers (explicit `TODO` and pending-run tags), recomputes SHA-256 digests of every approved stage's inputs, and marks upstream-modified downstream stages as `stale`.
2. **`check-readonly`:** Captures (`--create`) and verifies (`--verify`) a deterministic SHA-256 inventory of tracked files strictly inside the active paper workspace before and after read-only critic execution. Any added, modified, or deleted file triggers exit code 1, providing tamper detection on harnesses lacking hard filesystem write locks.
3. **`review-preflight`:** Executes mechanical provenance checks prior to spawning LLM critics:
   * *Citation and snapshot parity:* Extracts every Pandoc (`[@key]`, `@key`) and LaTeX (`\cite*{key}`) citation across `manuscript/sections/*.md` (stripping fenced code blocks and HTML comments), verifying 1:1 presence in `literature/references.bib` and `literature/citation_ledger.json`, blocking any `unverified_needs_human_check` entry, and confirming every `verified_source` entry resolves to a saved file under `literature/sources/`.
   * *Non-synthetic and BYO provenance:* Rejects any manuscript reference to the isolated `dry_run/` smoke-test directory, any run marked `is_synthetic: true` in `provenance_index.json`, `run_manifest.json`, or `metrics.json`, and any `origin: "user_byo"` run lacking `user_attested_non_synthetic: true`, while surfacing `git_dirty: true` runs as Major warnings.
   * *Inline run-to-metric matching:* Parses every inline provenance marker `<!-- run:<run_id> -->` and audits every decimal token $v$ with $d$ fractional digits in the immediately following blank-line-delimited paragraph or table block against the flattened numeric set $\mathcal{M}(r)$ of canonical `metrics.json` for run $r$. A decimal token $v$ passes if there exists $m \in \mathcal{M}(r)$ satisfying:

   $$|m - v| \le \epsilon(d) \;\lor\; \Big(0 \le m \le 1 \;\land\; |100m - v| \le \epsilon(d)\Big), \quad \epsilon(d) = 0.55 \times 10^{-d}$$ {#eq:decimal-match}

   where the second disjunct permits standard proportion-to-percentage conversion (e.g., $0.854 \to 85.4\%$) strictly when $m \in [0, 1]$, and $\epsilon(d)$ accommodates half-up/half-even rounding without tolerating fabricated shifts. Crucially, `po_tools.py` restricts automated regex matching to decimal tokens (`\d+\.\d+`) to avoid false alarms on section numbers, epoch counts, or hardware specs—deliberately delegating integer-count auditing, metric-key swapping within the unordered set $\mathcal{M}(r)$, unit-ambiguous $[0, 1]$ scaling, and untagged quantitative paragraphs to `po-evidence-auditor`.
4. **`format-verify`:** Enforces supply-chain, conversion, and anonymity invariants across Stage 9. First, it inspects `.zip` and `.tar.*` template archives before extraction for Zip Slip (`..` or leading `/`), symlink/hardlink members, and active TeX shell-pipe primitives (`\write18`, `\immediate\write18`, `\input{|...}`) after stripping `%` comments. Second, it verifies `.md`-to-`.tex` parity across citations, `\label{}` anchors, and non-dimension decimal tokens (filtering LaTeX units such as `0.85\linewidth` and `10.5pt`). Third, it parses TeX `.log` and `.aux` telemetry for undefined references, missing graphics, and `Overfull \hbox > 2pt` warnings. Finally, when `submission_mode == "double-blind"`, it scans all submission `.tex` files (including `%` comments) for local user paths (`/Users/`, `/home/`, `C:\Users\`), non-anonymous GitHub URLs, and camera-ready toggles (`\iclrfinalcopy`, `\usepackage{cvpr}`).

## Experiment Safety, Visual Provenance, and Context Offloading {#sec:method-safety}

Stage 3 (`po-exp-code`) enforces a safe bash runner contract to isolate experiments from user source code and prevent smoke tests from contaminating paper tables. Every runner uses `set -euo pipefail`, double-quoted paths, offline telemetry defaults (`WANDB_MODE=offline`), non-git fallback (`git_commit: "none"`, `git_dirty: null`), and CLI secret plus `$HOME` redaction inside logged `cmd` strings. On startup, each runner writes `run_manifest.json` (`status: "running"`) and registers `trap finalize EXIT` so `finished_at`, `exit_code`, and final status are recorded even on crash. Quantitative outputs are written atomically (`metrics.json.tmp` renamed via `os.replace`, capped under 10 KB), while `--dry-run` writes strictly to a segregated `dry_run/<run_id>/` tree with `is_synthetic: true`.

Two additional mechanisms protect context budgets and visual integrity. First, rather than embedding full paper abstracts inside `citation_ledger.json`, Stage 1 stores raw primary-source API snapshots in `literature/sources/<citekey>.json` and keeps only compact pointers and 1--2 sentence summaries in `citation_ledger.json`. Let $S_{\text{led}}$ and $S_{\text{src}}$ denote the byte sizes of `citation_ledger.json` and `literature/sources/`, respectively; the ledger context offload ratio is $R_{\text{off}} = (1 - S_{\text{led}} / (S_{\text{led}} + S_{\text{src}})) \times 100\%$, saving context across all non-citation stages while allowing `po-citation-auditor` to load raw snapshots on demand. Second, Stage 5 (`po-visuals`) mandates that all newly generated quantitative plots be rendered by version-controlled Python scripts (using optional `matplotlib`) reading directly from canonical non-synthetic `metrics.json` or `series.csv`—with zero hardcoded data arrays and zero generative raster tools on numerical data—exporting colorblind-safe, dual-encoded vector PDFs with stripped metadata alongside high-DPI PNG previews inspected visually before recording completion in `visuals/manifest.md`.

## Flat Read-Only Critic Topology, Paranoid TeX Sandbox, and Multi-Harness Packaging {#sec:method-critics}

Stage 7 (`po-review`) spawns five stateless read-only critic personas (`agents/po-*.md`, each `<= 6,000` bytes) **flat at depth one in parallel** directly from the root session (Figure~\ref{fig:architecture}, Layer 3a): `po-peer-reviewer` (originality, ablations, overclaims, prose anonymity), `po-evidence-auditor` (decimal and integer metric fidelity, BYO/synthetic provenance, plot script alignment), `po-citation-auditor` (offline BibTeX/ledger parity and claim-vs-source abstract fidelity), `po-visual-format-critic` (multimodal figure legibility in Stage 7 and chunked 4--5 page PDF layout review in Stage 9), and `po-clarity-reader` (naive external reader auditing undefined notation, unexplained acronyms, and logical jumps). Unlike EGM's nested `synthesizer` agent [@google2026egm], flat parallel dispatch avoids nesting failures across Antigravity and Claude Code Cowork, caps each critic at 1,500 output tokens, and logs a 4-state `Reviewer Status` ledger (`completed`, `skipped_not_applicable`, `carried_forward`, `not_run`) so missing critics are never silently equated with zero defects. On Claude Code, five matching read-only adapters (`.claude-plugin/agents/po-*.md`) restrict each critic's `tools:` allowlist strictly to `Read, Grep, Glob`.

Because static regex scanning of LaTeX sources can be bypassed by macro indirection (e.g., `\csname write18\endcsname`), Stage 9 (`po-format`) invokes `pdflatex` inside a paranoid native TeX wrapper (`openin_any=p openout_any=p pdflatex -interaction=nonstopmode -halt-on-error --no-shell-escape`, where `p` requests paranoid mode disallowing dotfiles and parent-directory access), suppresses PDF identity metadata via `\hypersetup{pdfauthor={},pdfcreator={},pdfproducer={}}` and TeX trailer directives, and audits compiled PDFs with `pdfinfo`. As we empirically verify in Section~\ref{sec:exp-rq3}, `--no-shell-escape` and `openout_any=p` hold under TeX Live 2026, whereas `openin_any=p` became an upstream no-op. Finally, `scripts/pack_plugin.py` synchronizes all five manifests (`plugin.json`, `.claude-plugin/{plugin,marketplace}.json`, `.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json`) and emits byte-reproducible ZIP archives (fixed ZIP timestamps `1980-01-01`, sorted traversal, normalized permissions) across Antigravity, Claude Code, and Codex.
